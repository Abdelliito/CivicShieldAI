The canonical PostgreSQL scripts are `001_schema.sql` and `002_seed.sql`.
`001_schema.sql` creates the complete relational schema in a fresh database.
`002_seed.sql` contains **synthetic Lahore demonstration data only** and refuses
to run without explicit opt-in or if user accounts already exist.

Using PostgreSQL's `psql` from the project root, with `POSTGRES_URL` set to your
normal `postgresql://` connection URL (omit SQLAlchemy's `+psycopg2` driver suffix):

```powershell
psql "$env:POSTGRES_URL" -v ON_ERROR_STOP=1 -f database/001_schema.sql
# Optional local demonstration seed; never run this against production data.
psql "$env:POSTGRES_URL" -v ON_ERROR_STOP=1 -c "SET civicshield.demo_mode = 'on';" -f database/002_seed.sql
```

Alternatively, the FastAPI startup creates the same schema from SQLAlchemy.
Startup then runs `003_photo_first_workflow.sql` inside a transaction, protected
by a PostgreSQL advisory lock. Existing attachments receive empty analysis JSON;
existing assignments keep full-report access, and no worker is selected directly.
The upgrade adds only `attachments.analysis`, `assignments.sharing_scope` and
`assignments.worker_id` plus the sharing-scope constraint. It never removes rows,
rewrites reports, or replaces the database. It is safe to run repeatedly.
Operators using SQL directly should apply the same upgrade after `001_schema.sql`:

```powershell
psql "$env:POSTGRES_URL" -v ON_ERROR_STOP=1 -1 -f database/003_photo_first_workflow.sql
```

Set `DEMO_MODE=true` explicitly in a local `.env` to seed the same demonstration
through Python. Leave it false for production and provision an administrator with
`python -m app.create_admin` from `backend`. No production accounts are created
automatically. Synthetic completion images are regenerated by demo startup and
are labeled as illustrations.

Schema and seed reproducibility checks, from `backend`:

```powershell
../.venv/Scripts/python.exe export_sql.py
../.venv/Scripts/python.exe verify_sql.py
```

These tools use uniquely generated temporary PostgreSQL schemas, clean up those
schemas, and preserve all application data. Exporting the demo seed requires
`DEMO_MODE=true`. Verification executes the delivered SQL and checks its foreign
keys, constraints, incident records, role accounts, and risk history on PostgreSQL.
